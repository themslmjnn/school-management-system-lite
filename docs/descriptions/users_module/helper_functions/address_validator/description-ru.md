# validate_address

**Модуль:** `users/utils/validators.py`
**Используется в:** валидаторе поля `address` в схемах пользователей
(`CreateUserAdmin` и схемы обновления профиля)

## Назначение

Нормализует необязательный адрес, чтобы сохранялся только чистый однострочный
текст. Пустой ввод или ввод из одних пробелов считается отсутствием адреса.

## Сигнатура

    validate_address(cls, address: str) -> str | None

**Возвращает:** нормализованный адрес.
**Исключение:** `PydanticCustomError`, возвращается как ошибка 422 для поля `address`.

## Шаги обработки

1. Нормализация пробелов: удаляются пробелы по краям, любая последовательность
   пробельных символов (пробелы, табуляции, переводы строк) заменяется одним
   пробелом.
2. Если ничего не осталось, возвращается `None`.
3. Проверяется длина нормализованного значения.
4. Значение отклоняется, если содержит управляющие символы.
5. Возвращается нормализованное значение.

## Правила валидации

| Правило | Значение |
|---|---|
| Наличие | Необязательное поле |
| Максимальная длина | 150 символов после нормализации (`ADDRESS_MAX_LENGTH`, соответствует колонке `String(150)`) |
| Пробелы | Сводятся к одиночным пробелам; результат — одна строка |
| Пустое значение или одни пробелы | Сохраняется как `NULL`, а не как пустая строка |
| Управляющие символы | Запрещены (например, `\x00`) |
| Остальные символы | Не ограничиваются: буквы любых алфавитов, цифры, знаки вроде `,` `/` `#` допустимы |

## Коды ошибок

| Код | Условие |
|---|---|
| `invalid_address_length` | Длина после нормализации больше 150. |
| `invalid_address_characters` | Содержит управляющий символ. |

## Примеры

| Ввод | Результат |
|---|---|
| `"   "` | `None` |
| `"  12  Main \n St  "` | Принято, возвращается `12 Main St` |
| `"Tashkent, Chilanzar 7, apt. 12/3"` | Принято |
| Адрес из 150 символов | Принято |
| Адрес из 151 символа | Отклонено, длина |
| `"Main St\x00"` | Отклонено, управляющий символ |

## Примечания по реализации

- Длина проверяется здесь, а не через `Field(max_length=150)`, потому что
  ограничение Field выполняется до нормализации и учитывало бы лишние пробелы.
  В схеме остаётся щедрый `max_length` (200) только как защита от слишком
  больших входных данных.
- Пустые строки превращаются в `None`, поэтому в колонке хранится либо
  настоящий адрес, либо `NULL`.
- Управляющие символы отклоняются, потому что PostgreSQL не может хранить `\x00`
  в текстовых колонках; без этой проверки такой ввод приводит к ошибке 500.
- Набор символов намеренно не ограничен, так как реальные адреса содержат
  много знаков и алфавитов.

## Ограничения

- Нет проверки того, что адрес реально существует.
- Переводы строк внутри адреса не сохраняются.
