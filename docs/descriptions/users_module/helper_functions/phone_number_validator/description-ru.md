# validate_phone_number

**Модуль:** `users/utils/validators.py`
**Используется в:** валидаторе поля `phone_number` в схемах пользователей
(`CreateUserAdmin` и схемы обновления профиля)

## Назначение

Проверяет номер телефона в международном формате и приводит его к
каноническому виду (`+` и цифры без пробелов). Именно этот вид сохраняется в
базе, поэтому уникальное ограничение `users.phone_number` сравнивает номера
одинаково независимо от того, как они были введены.

## Сигнатура

    validate_phone_number(phone_number: str) -> str

**Возвращает:** нормализованный номер, например `+998901234567`.
**Исключение:** `PydanticCustomError` с кодом `invalid_phone_number`,
возвращается как ошибка 422 для поля.

## Шаги обработки

1. Удаляются пробельные символы по краям.
2. Проверяется формат обрезанного значения: `+`, ненулевая цифра, затем цифры,
   при необходимости разделённые одиночными пробелами.
3. Пробелы удаляются, подсчитывается количество цифр.
4. Проверяется, что количество цифр в допустимом диапазоне.
5. Возвращается `+` и цифры.

## Правила валидации

| Правило | Значение |
|---|---|
| Префикс | Должен начинаться с `+` |
| Количество цифр | 8-15, `+` и пробелы не считаются (`PHONE_MIN_DIGITS`, `PHONE_MAX_DIGITS`) |
| Первая цифра | 1-9 (коды стран не начинаются с 0) |
| Допустимые символы | ASCII-цифры 0-9, одиночные пробелы, один `+` в начале |
| Пробелы | Только между двумя цифрами; нельзя подряд, после `+` и в конце |
| Любые другие символы | Запрещены (дефисы, скобки, точки, буквы, не-ASCII цифры) |

## Код ошибки

| Код | Условие |
|---|---|
| `invalid_phone_number` | Нарушено любое из правил выше. |

## Примеры

| Ввод | Результат |
|---|---|
| `+998901234567` | Принято |
| `+998 90 123 45 67` | Принято, возвращается `+998901234567` |
| `  +7 999 123 45 67 ` | Принято, возвращается `+79991234567` |
| `+12345678` / `+123456789012345` | Принято (8 / 15 цифр) |
| `998901234567` | Отклонено, нет `+` |
| `+1234567` / `+1234567890123456` | Отклонено, 7 / 16 цифр |
| `+0123456789` | Отклонено, ведущий 0 |
| `+998  90 123 45 67` | Отклонено, пробелы подряд |
| `+ 998901234567` | Отклонено, пробел после `+` |
| `+998-90-123-45-67` | Отклонено, дефис |

## Примечания по реализации

- Формат проверяется на исходной строке, потому что предварительное удаление
  пробелов скрыло бы пробелы подряд и пробелы в неправильных местах.
- Сохраняемое значение не длиннее 16 символов и помещается в колонку `String(20)`.
- В схеме остаётся только `max_length=30` как защита от слишком больших данных.
  Это длина самого длинного допустимого ввода (`+`, 15 цифр, 14 одиночных
  пробелов). Основная проверка выполняется здесь.
- Используется `[0-9]`, а не `\d`, чтобы похожие не-ASCII цифры не обходили
  уникальное ограничение.

## Ограничения

- Номер не сверяется с реальными кодами стран и национальными форматами.
- Разные записи одного номера (например, местный префикс и международный)
  считаются разными номерами.
