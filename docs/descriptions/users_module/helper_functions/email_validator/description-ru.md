# validate_email

**Модуль:** `users/utils/validators.py`
**Используется в:** валидаторе поля `email` в схемах пользователей
(`CreateUserAdmin` и схема изменения email)

## Назначение

Проверяет адрес электронной почты и приводит его к нижнему регистру без
пробелов по краям. Именно это значение сохраняется в базе, поэтому уникальное
ограничение `users.email` считает `Anna@School.com` и `anna@school.com` одним и
тем же адресом.

## Сигнатура

    validate_email(email: str) -> str

**Возвращает:** нормализованный email.
**Исключение:** `PydanticCustomError` с кодом `invalid_email`, возвращается как
ошибка 422 для поля.

## Шаги обработки

1. Удаляются пробелы по краям, значение приводится к нижнему регистру.
2. Проверяется длина нормализованного значения.
3. Всё значение целиком проверяется по допустимому шаблону.
4. Возвращается нормализованное значение.

## Правила валидации

| Правило | Значение |
|---|---|
| Максимальная длина | 50 символов после нормализации (`EMAIL_MAX_LENGTH`, соответствует колонке `String(50)`) |
| Знак `@` | Ровно один |
| Часть до `@` | Английские буквы, цифры, `_` и `.`; не может начинаться и заканчиваться на `.`; точки подряд запрещены |
| Часть после `@` (домен) | Метки из английских букв, цифр и дефисов, разделённые точками; метка не может начинаться или заканчиваться дефисом |
| Окончание домена | Минимум одна точка; последняя метка состоит из 2 и более английских букв |
| Другие символы | Запрещены (`+`, `-` в части до `@`, пробелы, неанглийские буквы) |

## Код ошибки

| Код | Условие |
|---|---|
| `invalid_email` | Email слишком длинный или нарушает любое правило формата выше. |

## Примеры

| Ввод | Результат |
|---|---|
| `anna_ivanova@my-school.edu` | Принято |
| `a.b@x.com` | Принято |
| `A@X.COM` | Принято, возвращается `a@x.com` |
| `  a@x.com  ` | Принято, возвращается `a@x.com` |
| `a@@x.com` | Отклонено, два `@` |
| `a..b@x.com`, `.a@x.com`, `a.@x.com` | Отклонено, неверное расположение точек |
| `a@x..com`, `a@-x.com`, `a@x.com.` | Отклонено, неверный домен |
| `a@x`, `a@x.c` | Отклонено, нет корректного окончания домена |
| `user+tag@x.com`, `user-name@x.com` | Отклонено, символ не разрешён в части до `@` |
| `анна@x.com` | Отклонено, неанглийские буквы |
| Email из 51 символа | Отклонено, длина |

## Примечания по реализации

- Значение приводится к нижнему регистру до проверки, поэтому шаблон содержит
  только строчные буквы, а сохраняемое значение каноническое.
- Длина проверяется после удаления пробелов по краям, поэтому лишние пробелы не
  приводят к ложному отказу. В схеме остаётся щедрый `max_length` как защита от
  слишком больших данных.
- Правила намеренно строже стандарта (RFC 5322) в части до `@`. Дефис
  разрешён только в домене.
- Адрес используется для доставки ссылки активации, поэтому проверка формата
  не позволяет создать аккаунт, который невозможно активировать из-за
  некорректного адреса.
- Проверка подтверждает только корректность формата, но не существование
  почтового ящика.

## Ограничения

- Адреса с `+` или `-` в части до `@`, адреса в кавычках, домены в виде
  IP-адреса и интернационализированные (неанглийские) адреса отклоняются.
- Окончания доменов с цифрами или дефисами (например, punycode) отклоняются.
- Существование почтового ящика не проверяется.
